# 模块解读 03：工具注册与执行框架

> 本文拆解 `autocode/tools/`：`Tool` 抽象基类、
> `ToolRegistry` 注册表、参数 Schema 自动生成，以及主循环里工具调用的执行与结果回填。
> 全文基于本项目 `autocode/` 包（模块解读，供自研参考）。

## 1. 模块职责

让 LLM 拥有「动手能力」需要三件事，正好对应三块代码：

1. **给 LLM 看说明书** —— `Tool.get_schema()` 把工具名/描述/参数 Schema 转成模型能读的 JSON；
2. **一个工具目录** —— `ToolRegistry` 注册、查询、启停、延迟发现（deferred）工具；
3. **执行与回填** —— `Agent` 收到 `ToolCallComplete` 后解析参数 → 校验权限 → 执行 →
   把 `ToolResult` 写回对话历史，进入下一轮。

内置工具分两类：
- **编码工具**（`create_default_registry`）：`ReadFile` / `WriteFile` / `EditFile` /
  `Bash` / `Glob` / `Grep`；
- **笔试题演示工具**（`register_demo_tools`）：`Calculator` / `Search` / `Weather` /
  `Todo` —— 全部本地、确定性、离线可测，供演示「工具注册→自主调用」机制。

## 2. 核心数据结构

### Tool 抽象基类（`autocode/tools/base.py`）

```python
class Tool(ABC):
    name: str                                  # 模型看到的工具名
    description: str                           # 用途说明，供模型决策
    params_model: type[BaseModel]              # pydantic 参数模型
    category: ToolCategory = "read"            # read | write | command
    is_concurrency_safe: bool = False
    should_defer: bool = False                 # 延迟发现（ToolSearch 用）

    @property
    def is_read_only(self) -> bool: ...        # category == "read"

    def get_schema(self) -> dict[str, Any]:
        schema = self.params_model.model_json_schema()   # pydantic → JSON Schema
        return {"name": ..., "description": ..., "input_schema": schema}

    @abstractmethod
    async def execute(self, params: BaseModel) -> ToolResult: ...
```

**用 pydantic 模型声明参数**是一招妙棋：一份定义同时产出 `get_schema()` 喂给 LLM、
`execute()` 拿到强类型对象、以及参数非法时的自动报错。

### ToolResult（`base.py`）

```python
@dataclass
class ToolResult:
    output: str
    is_error: bool = False
```

主循环把 `is_error` 原样写回给模型，模型看到错误会自己修正参数再试（self-healing）。

### ToolRegistry（`autocode/tools/__init__.py`）

```python
class ToolRegistry:
    def register(self, tool): ...          # 名字 → 实例
    def get(self, name) -> Tool | None: ...
    def enable(name) / disable(name) / is_enabled(name): ...
    def get_all_schemas(protocol) -> list[dict]:   # 全部启用工具 → Schema 列表
    def get_deferred_tool_names() / search_deferred(query, ...): ...  # 延迟发现
```

注册表还负责**延迟发现**：`should_defer=True` 的工具不随主列表进 system prompt，
而是等 LLM 显式搜索到（`ToolSearchTool`）才临时注入——控制每轮 tool 数量与 token。

## 3. 关键流程

### 演示工具实现范式（以 Calculator 为例，`autocode/tools/calculator.py`）

```python
class Params(BaseModel):
    expression: str = Field(description="要计算的数学表达式…")

class Calculator(Tool):
    name = "Calculator"
    description = "安全求值数学表达式…"
    params_model = Params
    category = "read"
    is_concurrency_safe = True

    async def execute(self, params: Params) -> ToolResult:
        # AST 白名单：只允许 四则/幂/取模/括号/一元符号，
        # 从根上杜绝 eval/exec 任意代码执行
        ...
```

### 工具调用 → 执行 → 回填（`agent.py` 主循环内）

```
1. collector 收到 ToolCallComplete → response.tool_calls += ...
2. if not response.tool_calls: 直接回答并结束本轮
3. partition_tool_calls(calls, registry)
       → 按 is_concurrency_safe 把可并发的工具聚成同一批（ToolBatch）
4. 每个 ToolCall：
       a. 权限检查（hook 拦截 / PermissionChecker 决策，见 06 章）
       b. 通过 → await registry.get(name).execute(params)
       c. 结果 → ToolResultEvent(tool_id, tool_name, output, is_error)
       d. 写回 conversation（ToolResultBlock，tool_use_id 关联）
5. 循环回到顶部，把带结果的对话再发给 LLM
```

关键点：**工具结果与模型上一轮的工具调用通过 `tool_use_id` 配对**，保证消息历史里
每个 assistant 工具调用都有对应 tool_result，符合 Anthropic / OpenAI 的 API 约束。

### 并发的批执行（`StreamingExecutor`）

`submit(coro)` 攒任务 → `collect_results()` 用 `asyncio.gather` 并发跑完并按提交顺序
返回，异常统一包成 `ToolResult(output="Tool execution error: …", is_error=True)`，
不让单个工具异常拖垮整轮。

## 4. 要点小结

1. **为什么参数用 pydantic 模型声明，而不是手写 JSON Schema？**
   一份 `Params` 类同时产出三样：喂给模型的 Schema、execute 拿到的强类型对象、非法参数
   的自动报错。手写 JSON Schema 容易与解析逻辑脱节。`model_json_schema()` 转一次即可。

2. **ToolRegistry 的 disable 有什么用途？**
   权限 / 会话上下文需要临时禁用某工具（如高危工具在只读模式禁掉）时，`is_enabled`
   会让它从 `get_all_schemas` 里消失——模型根本看不到，比「允许调用但执行时报错」更干净。

3. **`is_concurrency_safe` 是做什么的？**
   标记一个工具能否并发执行。`partition_tool_calls` 据此把连续的安全工具聚到同一
   ToolBatch 并发跑，其余顺序执行。文件编辑类工具通常标记为不安全（避免并发写冲突）。

4. **延迟发现（should_defer / ToolSearchTool）解决什么问题？**
   工具上百个时全量塞给模型既费 token 又稀释注意力。延迟工具平时不暴露，模型想用时先
   调 `ToolSearchTool` 搜到目标工具的 Schema，再发起真正的调用——按需加载。

5. **演示工具为什么全用「确定性 mock」？**
   calculator、search 允许用 mock。确定性（同输入同输出）让测试可离线、可复现：
   Calculator 用 AST 白名单而非 eval（防注入），Search 用内置知识库子串匹配，
   Weather 用城市名哈希生成伪数据，Todo 用 `session_id.json` 按会话隔离。
